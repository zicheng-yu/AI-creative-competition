### 1.7 Trace 文献里实际引用、且没有写进生成器的数字

生成器**不读取**这些数。它们只说明「为什么工作负载长这样、以及我们没有假装拟合了 CDF」。代码里的副本在 `js_computesim/trace_anchors.py`。

- Weng 等，*MLaaS in the Wild*，NSDI 2022。阿里 PAI 2020 年 7–8 月，6742 GPU，超过 120 万 task、750 万 instance。实例运行时间中位数 23 分钟；文中对比 Philly 中位数 26 分钟。工作日提交略高于周末；除白天外午夜也是提交高峰，但午夜任务更小。只有约 6% 的 task 指定 GPU 型号。异构卡是 T4 / P100 / V100 / V100M32 / Misc，**没有**昇腾、寒武纪、海光。
- Hu 等，*Characterization and Prediction of Deep Learning Workloads in Large-Scale GPU Datacenters*，SC 2021。Helios 四个集群，2020-04 至 2020-09，802 节点、6416 GPU、约 336 万作业。利用率约 65%–90%，0–8 点下降约 5–8 个百分点，因为训练作业会跨夜跑。GPU 作业未成功结束的比例 37.6%（含用户取消）。
- Jeon 等，Philly，USENIX ATC 2019。这里只转引 Weng 论文里的 26 分钟中位数，没有重算 Philly。

因此：夜间预训练高于白天，是赛题场景，**不是** Helios 的实测夜降。五类任务占比也不是 PAI 的标注——PAI 调度器看不到训练还是推理。

区域划分：苏南 = 宁锡常苏镇，苏中 = 通扬泰，苏北 = 徐连淮盐宿。南通在行政上是苏中，绿电曲线仍按沿海城市单独给。

### 2.2 芯片池与 η、算子增益

每个节点（含枢纽）使用同一套铭牌份额：CPU 0.22、昇腾 0.18、寒武纪 0.10、海光 0.12、NVIDIA 0.28、超算 0.10。没有全省芯片普查支持这组数。

`η[k,m]` 是任务 k 在池 m 上能变成「参考 EFlops」的比例，`operator_gain` 是软件栈额外倍率，有效系数 = η × gain。两张表都在 `configs/pools.yaml`，全部是假设。PAI 2020 只支持「大多数任务可以跨 GPU 代际、但效率不该当成 1」这件事，不支持表里的具体小数。

### 2.3 功耗、PUE 微调和 IT 功率尺度

设施功率（每个仍在线的池，再按节点相加）：

```text
P_peak_MW = 可用铭牌 EFlops × it_kw_per_eflops / 1000
P_it      = P_peak × (idle + (1 - idle) × u^α)
PUE(u)    = PUE_base × (1 + 0.04 × u_node) × 故障倍率
P_facility = PUE(u) × Σ P_it
```

- `it_kw_per_eflops = 1000`。这是沙盘尺度。271.8 EFlops 因此对应 271.8 MW 的江苏 IT 铭牌。它不是官方的「EFlops 换瓦特」。绝对电量、电费、碳排都随这个系数线性变化；同一系数下比策略才有意义。
- `α = 1.2`。Barroso & Hölzle, *The Case for Energy-Proportional Computing*, IEEE Computer 2007，说明服务器空载功耗很高、动态部分接近线性。这里的 α>1 是凸性旋钮，不是他们的拟合值。
- 空载比例：CPU 0.50，超算 0.40，加速卡池 0.22–0.28。CPU 的 0.50 只是贴近该文「常常一半上下」的数量级。
- 利用率抬升 PUE 的系数 0.04 是假设。故障倍率可以让当小时 PUE 高于 1.48。
- 健康度为 0 的节点本小时不计功率，也不接任务。

电费 = 全部设施电量 × 当小时目录电价。绿电**不**自动降电费，只减少碳排：

```text
绿电电量 = min(设施电量, 可签约绿电功率 × 1 h)
碳排     = (设施电量 - 绿电电量) × 节点排放因子
```

### 2.4 绿电 24 小时曲线

可签约功率 = 全市装机 MW × `assumption_contract_fraction`。默认比例 **0.001**。没有公开的「数据中心签了多少绿电」。0.1% 使盐城风电合同大约 9.4 MW，和该市约 15 MW 的 IT 铭牌同一数量级，大发场景下绿电能被调度看到，常规小时也不会变成 100% 绿电。

容量因子形状：

- 风：`clip(0.36 + 0.12 × cos(2π (h - 2) / 24), 0, 1)`。24 个整点上余弦和约等于 0，均值接近 0.36。不是测风塔。
- 光：6 点到 18 点的正弦，正午峰值 0.72，夜间为 0。不是辐照观测。

7 天重复同一条 24 小时曲线，没有天气噪声。其他城市绿电为 0。

### 2.5 负载

`configs/workload.yaml`：

- 平均到达 = 271.8 × 0.65 × 任务占比，再乘日变化、周末系数和均值 1 的对数正态噪声（σ = 0.05）。0.65 和占比都是假设。占比：推理 0.42、通算 0.18、预训练 0.16、微调 0.16、超算 0.08。
- 日变化在加载时除以自身均值。推理和通算白天高，预训练和微调夜间高。
- 周末系数：推理 0.90、通算 0.88、微调 0.95、超算 0.97、预训练 1.00。只对应 Weng 等「工作日略高」的方向，0.90 不是文中的数。周一是第 1 天，第 6、7 天是周末。
- 来源城市 = GDP × 区域倾斜后归一。推理对苏南 ×1.8、苏中 ×1.0、苏北 ×0.55。枢纽不产生需求。倾斜是假设，用来形成「苏南推理、苏北绿电」的可调度格局。
- 每小时以概率 0.06 额外注入 1.2 倍推理均值的突发推理，优先级更高，与日变化独立。
- 截止期（小时）：推理 1、通算 4、微调 8、超算 12、预训练 24。时延 SLA（毫秒）：推理和通算 5，其余 10。
- 局末仍未完成的积压记入 SLA 未完成，各策略一样，避免快结束时把长作业藏起来。

## 3. 四个压测场景

物理参数以上面的夏季工作日为底。

## 4. 复现

```bash
cd 02-sansu-computing-dispatch
python -m pip install -r requirements.txt
python -m pytest -q
python scripts/run_baselines.py --seed 313
```

同一 `scenario` 与 `seed`，到达、故障时刻和随机策略动作都不变。预测接口 `planning_snapshot()` 把生成器的剩余到达原样交给 MILP；换成真实预测器时替换这份数组即可，步进逻辑不用改。

## 5. 这版故意没做的事

- 没有把 Alibaba v2020 / v2025 / v2026、Helios、Philly 的行数据拟合进到达过程。
- 没有 Electricity Maps 或华东电网的小时碳强度。
- 没有沪、浙、皖的月度代理购电电价，也没有苏南/苏北分价，因为省级公告未分区域。
- 没有把 271.8 EFlops 解释成某一种芯片精度下的实测功耗。
- MILP 求解和 Safe-RL 训练不在 YOU-268 里。环境只提供 `planning_snapshot()`、偏好动作、显式四维动作和 `info["cost"]`。
